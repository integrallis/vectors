# Prospective convolution capability cohort

This dispatch-only protocol compares the unchanged published and candidate artifacts in 3,328 fixed fresh-process pairs. It requires eight independent hosts each for EPYC7763/AVX2, EPYC9V74/AVX2 and EPYC9V74/AVX512 (128 pairs per host), plus four Neoverse-N2/SVE128 hosts (64 pairs each). Every arm retains five blocks of at least one measured second, the published input/history workload, cold allocation before initialization, exact candidate cold/hot/history checks, and the original resource/latency/0.02 precision limits.

The previous cohort remains failed. Its within-process blocks were stable, but published fork times varied and nominally identical 9V74 hosts exposed different SIMD capabilities. Sample planning uses the retained paired log deviations: approximately 322–397 independent pairs for7763,491 for9V74/AVX2,257 for9V74/AVX512 and34 forN2 before between-host uncertainty. The declared1024 pairs per x86 stratum plus eight independent hosts, and256 ARM pairs/four hosts, provide additional margin. These are prospective planning estimates, never a precision guarantee.

There are exactly128 x86 and4 ARM hardware-admission attempts, with at most24 simultaneous jobs. Before any build or timing, a matching host claims the first available one of its fixed stratum slots using an S3 conditional PUT (`If-None-Match: *`). No host can replace a failed admitted host; no measured result affects selection. All132 admission receipts are mandatory. Unmatched hosts and hosts after their stratum's slots are full perform no measurements. If the fixed attempts do not fill every slot, the cohort is incomplete. A later attempt requires its own declared protocol; this run is never extended adaptively.

The one-use admission URL map is stored as a repository secret. Generate a fresh empty cohort prefix and prove conditional PUT rejects overwrites before dispatch. Keep URLs out of logs/artifacts. The manifest records source/runtime hashes, actual JVM capabilities and immutable claimed slot. Results are assessed separately per capability stratum, with sorted host keys, equal host weights and the frozen hierarchical bootstrap. No prior observations are pooled. Expected aggregate runner use is20–24 hours, approximately60–90 minutes at the declared parallelism; timing is fixed by counts, never stopped on a favorable interval.
