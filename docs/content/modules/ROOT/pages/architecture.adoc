= Architecture
:navtitle: Architecture

This page describes the module layout, dependency graph, and key architectural decisions in the Vectors library.

== Module Overview

Vectors is a multi-module Gradle project.
Each module has a single responsibility and exposes its API via `api` dependencies so that downstream modules can compose them.

[cols="2,5", options="header"]
|===
| Module | Description

| `vectors`
| Umbrella artifact for the embedded engine. Re-exports `vectors-db`.

| `vectors-core`
| SIMD distance kernels (dot product, L2, cosine), vector type abstractions, similarity functions.
Foundation module with no internal dependencies.

| `vectors-storage`
| Off-heap memory management via `MemorySegment` and `Arena`.
Arena-scoped allocation, mmap file I/O, storage backend abstraction.

| `vectors-storage-s3`
| Opt-in AWS SDK runtime for `S3StorageBackend`.

| `vectors-quantization`
| Scalar (int8/int4), product (PQ), binary (BQ/BBQ), RaBitQ, extended RaBitQ, TurboQuant, and NVQ quantizers.
Training, encoding, and asymmetric distance estimation.

| `vectors-hnsw`
| HNSW graph index.
Multi-layer navigable small world graph with diversity-based neighbor selection and two-pass quantized search.

| `vectors-vamana`
| Vamana/DiskANN graph index.
Single-layer graph with graduated alpha pruning, medoid entry point, and two-pass quantized search.

| `vectors-ivf`
| IVF family indexes (IVF_FLAT, IVF_PQ).
Inverted file with k-means clustering, ADC lookup tables, and optional rescore.

| `vectors-db`
| Embedded vector database facade.
Unified `VectorCollection` API over all backends with metadata filtering, persistence, deletion, and compaction.

| `vectors-db-arrow`
| Opt-in Apache Arrow runtime for IPC import and export.

| `vectors-hybrid`
| Dense and text retriever SPIs with reciprocal-rank and weighted fusion.

| `vectors-spring-ai`
| Spring AI `VectorStore` adapter.

| `vectors-langchain4j`
| LangChain4j `EmbeddingStore` adapter.

| `vectors-spring-boot-starter`
| Spring Boot auto-configuration over `vectors-spring-ai`.

| `vectors-cache`
| Cache SPI and Caffeine implementation.

| `vectors-cache-jcache`
| JSR-107 bridge for `VectorCache`.

| `vectors-cache-langchain4j`
| LangChain4j embedding-model cache decorator.

| `vectors-cache-semantic-db`
| Semantic cache backed by `VectorCollection`.

| `vectors-cache-spring-ai`
| Spring AI embedding/chat cache decorators.

| `vectors-vcr-core`
| Framework-neutral model-call record/replay engine and cassette storage API.

| `vectors-vcr-semantic-db`
| Similarity-based cassette lookup backed by `VectorCollection`.

| `vectors-vcr-serde-avaje`
| Avaje JsonB cassette serialization.

| `vectors-vcr-serde-jackson`
| Jackson cassette serialization.

| `vectors-vcr-junit5`
| JUnit 5 lifecycle integration for VCR tests.

| `vectors-vcr-testng`
| TestNG lifecycle integration for VCR tests.

| `vectors-vcr-spring-ai`
| Spring AI chat and embedding model wrappers.

| `vectors-vcr-langchain4j`
| LangChain4j chat, embedding, and interceptor wrappers.
|===

These are the 30 Apache-2.0 modules published in {vectors-version}.

== Dual-Mode Operation

Every `VectorCollection` can run in one of two modes:

* **In-memory** -- all data lives on the Java heap, with no disk I/O.
Data does not survive process restart. Use it for ephemeral workloads and datasets that fit comfortably in RAM.

* **Persistent (mmap)** -- vectors and graph structures are memory-mapped from disk via `MemorySegment`.
Writes produce a new generation directory; a single atomic pointer flip (`CURRENT` file) makes the generation visible.
The OS page cache manages what stays in RAM.
A persistent collection directory has one in-process writer at a time; reopening a directory recovers the last committed generation, walking back if the newest generation is incomplete.

Switch between modes by providing a `storagePath` to the builder:

[source,java]
----
// In-memory
VectorCollection inmem = VectorCollection.builder()
    .dimension(384)
    .metric(SimilarityFunction.COSINE)
    .indexType(IndexType.HNSW)
    .build();

// Persistent
VectorCollection persistent = VectorCollection.builder()
    .dimension(384)
    .metric(SimilarityFunction.COSINE)
    .indexType(IndexType.HNSW)
    .storagePath(Path.of("/var/lib/vectors/my-collection"))
    .build();
----

== Index Type Comparison

[cols="1,2,2,2,2", options="header"]
|===
| Index | Search complexity | Build complexity | Memory overhead | Best for

| FLAT
| O(n) linear scan
| O(n)
| None
| Small datasets (< 100K), exact results

| HNSW
| Graph traversal; workload-dependent
| O(n log n)
| ~12 x M bytes/node
| General-purpose approximate search

| Vamana
| Graph traversal; workload-dependent
| O(n log n), 2-pass
| ~4 x R bytes/node
| Disk-oriented workloads, mmap-persistent indexes

| IVF_FLAT
| O(n / k x nprobe)
| O(n x k-means iterations)
| ~4 bytes/vector (cluster id)
| Large datasets with moderate recall requirements

| IVF_PQ
| O(n / k x nprobe), ADC
| O(n x k-means) + PQ training
| M bytes/vector (PQ codes)
| Maximum compression on large datasets
|===

See the xref:sizing.adoc[Sizing Guide] for capacity planning and tuning parameters.

== SIMD Strategy

Distance kernels use the Java Vector API (`jdk.incubator.vector`):

* **`SPECIES_PREFERRED`** for portability across hardware (128-bit, 256-bit, 512-bit lanes)
* **4x unrolled FMA accumulators** for dot product and L2 distance to saturate execution ports
* **Conditional FMA** -- `a.fma(b, c)` when the hardware has fast FMA, `a.mul(b).add(c)` otherwise
* **Scalar tail** for dimensions not divisible by the lane width
* A pure-scalar fallback (`ScalarVectorUtilSupport`) is always available

GGUF matrix-vector kernels quantize each activation once and reuse it across every weight row.
Large Q4_0, Q4_K, Q5_0, Q5_K, Q6_K, and Q8_0 matrices distribute independent rows across the
bounded common fork-join pool. Parallel execution is used only for memory segments that are
accessible from worker threads; confined segments stay on their owner thread. The default
crossover is 1,048,576 matrix elements, with a 4,194,304-element floor for Q8_0 because smaller
Q8_0 matrices are memory-bandwidth and scheduling limited.

MXFP4 model weights use the same bounded row scheduler. Its W4A8 kernel converts one activation to
Q8_0, decodes pairs of E2M1 nibbles through a Vector API lookup table, and accumulates signed
integer products with the combined E8M0 and activation scales. A prepared-activation overload lets
model runtimes reuse that conversion across projections with the same input. An exact
F32-activation path remains available when activation quantization is not acceptable.

Set `-Dvectors.gguf.parallel=false` to force serial GGUF execution, or raise the global crossover
with `-Dvectors.gguf.parallelThreshold=<elements>`. The active values are included in the
`vectors-core` startup diagnostic line.

An experimental Q4_0/Q8_0 signed-short pairwise kernel is available for measured GraalVM
deployments. It is disabled by default and activates only for 256-bit vectors and rows of at least
1,024 dimensions. The accepted Qwen3 profile uses both
`-Djdk.graal.MaximumInliningSize=10000` and `-Dvectors.gguf.q4ShortPairwise=true`; enabling only the
Vectors property can create substantial temporary Vector API allocations. See
`vectors-bench/jmh-results/graal-q4-short-pairwise.md` in the source repository for the exact JVM
revision, correctness gate, performance evidence, and rollback procedure.

== Memory Model

* **Vectors** are stored off-heap via `MemorySegment` in persistent mode, or as `float[][]` on the heap in memory mode.
* **Graph adjacency** (HNSW layers, Vamana neighbor lists) is always on-heap.
* **Quantized codes** (PQ, BQ, SQ) are stored in compact `byte[]` arrays with per-vector correction factors.
* **Arenas** scope the lifetime of mmap segments to a generation; closing a generation unmaps its files.
