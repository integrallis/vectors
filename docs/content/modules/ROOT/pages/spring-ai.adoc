= Spring AI Integration
:navtitle: Spring AI

Vectors provides a Spring AI `VectorStore` adapter and a Spring Boot starter. `JavaVectorsVectorStore` wraps a `VectorCollection` and an `EmbeddingModel`, implementing Spring AI's `VectorStore` interface as a drop-in, indexed replacement for `SimpleVectorStore`.

NOTE: Vectors requires JDK 25 with the Vector API enabled: run with `--add-modules jdk.incubator.vector`.

There are two ways to use Vectors with Spring AI:

* **Spring Boot starter** (recommended) — add one dependency and both a `VectorCollection` and a
  `VectorStore` are auto-configured for you. Start here.
* **Direct adapter** — build the `VectorCollection` and `JavaVectorsVectorStore` yourself. Use this
  when you are not on Spring Boot, or when you want full programmatic control over both objects.

== Quick Start (Spring Boot)

Add the starter:

[tabs]
====
Gradle::
+
[source,kotlin,subs="attributes+"]
----
dependencies {
    implementation("com.integrallis:vectors-spring-boot-starter:{vectors-version}")
}
----

Maven::
+
[source,xml,subs="attributes+"]
----
<dependency>
    <groupId>com.integrallis</groupId>
    <artifactId>vectors-spring-boot-starter</artifactId>
    <version>{vectors-version}</version>
</dependency>
----
====

With an `EmbeddingModel` already on the classpath, that is all the configuration you need. The
starter auto-configures **both** beans — you do not declare a `VectorCollection` yourself:

* `metric` defaults to `COSINE`.
* the collection `dimension` is inferred from `EmbeddingModel.dimensions()`.

Inject the auto-configured `VectorStore` and use the standard Spring AI API:

[source,java]
----
@Autowired
VectorStore vectorStore;   // auto-configured; no VectorCollection bean required

vectorStore.add(List.of(
    new Document("hello world"),
    new Document("goodbye world")));

List<Document> results = vectorStore.similaritySearch(
    SearchRequest.builder().query("hello").topK(5).build());
----

Override any default — index type, metric, an explicit dimension, on-disk persistence — through
`java-vectors.*` properties; see <<Spring Boot Properties>>. To supply your own `VectorCollection`
or `VectorStore`, declare a `@Bean` of that type and the matching auto-configured bean backs off
(`@ConditionalOnMissingBean`).

TIP: The adapter's Spring AI dependency is `compileOnly` and it binds only to the stable
`VectorStore` SPI, so one artifact works across Spring AI **1.0.x, 1.1.x, and 2.0.x** — you bring
your own Spring AI version. CI compiles and runs the adapter's tests against each line on every
change.

== Manual Wiring (Direct Adapter)

Without the starter, add `vectors-spring-ai` and wire the two objects yourself. This path needs
**both** a `VectorCollection` and a `JavaVectorsVectorStore` — the starter above creates them for
you:

[tabs]
====
Gradle::
+
[source,kotlin,subs="attributes+"]
----
dependencies {
    implementation("com.integrallis:vectors-spring-ai:{vectors-version}")
    implementation("org.springframework.ai:spring-ai-vector-store:1.1.4")
}
----

Maven::
+
[source,xml,subs="attributes+"]
----
<dependency>
    <groupId>com.integrallis</groupId>
    <artifactId>vectors-spring-ai</artifactId>
    <version>{vectors-version}</version>
</dependency>
----
====

Build a `VectorCollection`, then pass it together with an `EmbeddingModel` to
`JavaVectorsVectorStore.builder(embeddingModel, collection)`:

[source,java]
----
VectorCollection collection = VectorCollection.builder()
    .dimension(embeddingModel.dimensions())
    .metric(SimilarityFunction.COSINE)
    .indexType(IndexType.HNSW)
    .build();

VectorStore vectorStore = JavaVectorsVectorStore.builder(embeddingModel, collection)
    .collectionName("my-docs")   // used in observation metadata; default "default"
    .commitAfterAdd(true)        // commit after each add() so writes are searchable; default true
    .build();

// Standard Spring AI API
vectorStore.add(List.of(
    new Document("hello world"),
    new Document("goodbye world")));

List<Document> results = vectorStore.similaritySearch(
    SearchRequest.builder().query("hello").topK(5).build());
----

On `add()`, the store embeds the whole document list in one call through the model's batching API
(`embed(List, EmbeddingOptions, BatchingStrategy)`), so ingesting N chunks costs a few token-limited
provider round-trips rather than N — and it composes with the batch de-duplication in
`CachingEmbeddingModel`. The default `TokenCountBatchingStrategy` packs documents under the model's
token limit; override it with `.batchingStrategy(...)` (the Spring Boot starter reuses your
application's `BatchingStrategy` bean when one is present). The builder also validates at build time
that the model's dimension matches the collection's. `similaritySearch` embeds the query, translates
any filter expression, and maps hits back to Spring AI `Document` instances with their similarity
`score` populated.

=== Diversity re-ranking (MMR)

RAG retrieval often returns several near-duplicate chunks that waste the LLM context window. Enable
**Maximal Marginal Relevance** on the store to trade a little relevance for diversity — no second
datastore, no external rerank API:

[source,java]
----
VectorStore vectorStore = JavaVectorsVectorStore.builder(embeddingModel, collection)
    .mmr(0.6f)   // lambda: 1.0 = pure relevance, 0.0 = max diversity; typical 0.5-0.7
    .build();

// Every similaritySearch now over-fetches topK x 4 candidates and re-ranks them down to
// topK diverse-but-relevant results using the collection's metric.
List<Document> results = vectorStore.similaritySearch(
    SearchRequest.builder().query("hello").topK(5).build());
----

Use `.mmr(lambda, fetchMultiplier)` to control the candidate-pool size (default multiplier `4`).
MMR is computed server-side over the over-fetched pool via the fused-SIMD kernels — it runs on a
small candidate set, not the whole corpus, so the overhead is sub-millisecond for typical `topK`.

== Spring Boot Properties

Every setting is optional. When using the starter, override defaults via `application.yml`:

[source,yaml]
----
java-vectors:
  dimension: 1536          # optional — inferred from EmbeddingModel.dimensions() when unset
  metric: COSINE           # optional — defaults to COSINE
  index-type: HNSW         # defaults to FLAT
  quantizer: SQ8           # defaults to NONE
  storage-path: /var/lib/vectors/my-collection   # omit for a purely in-memory collection
  auto-commit-threshold: 1
  commit-after-add: true   # commit after each store.add(); set false for batch ingestion
  hnsw:
    m: 16
    ef-construction: 200
  vamana:
    max-degree: 64
    search-list-size: 128
    alpha: 1.2
----

The starter auto-configures:

* A `VectorCollection` bean. When a Spring AI `EmbeddingModel` bean is present, its `dimension` is
  inferred from the model unless you set `java-vectors.dimension` explicitly. Without an
  `EmbeddingModel`, `java-vectors.dimension` is required — the context fails at startup with a clear
  message if it is missing.
* A `JavaVectorsVectorStore` bean (conditional on an `EmbeddingModel` bean being present).

Both beans are `@ConditionalOnMissingBean`, so you can override either with a custom `@Bean`
definition.

== Filter Translation

Spring AI filter expressions are translated to the java-vectors `Filter` AST.
All standard operators are supported:

[cols="1,1", options="header"]
|===
| Spring AI | java-vectors

| `EQ`   | `Filters.eq()`
| `NE`   | `Filters.not(Filters.eq())`
| `GT`   | `Filters.gt()`
| `GTE`  | `Filters.gte()`
| `LT`   | `Filters.lt()`
| `LTE`  | `Filters.lte()`
| `IN`   | `Filters.inStr()` / `Filters.inNum()`
| `NIN`  | `Filters.not(Filters.inStr())`
| `AND`  | `Filters.and()`
| `OR`   | `Filters.or()`
| `NOT`  | `Filters.not()`
|===

== Embedding Cache

Combine with `vectors-cache-spring-ai` to cache embedding model calls:

[source,java]
----
VectorCache<String, float[]> cache = CaffeineVectorCache.<String, float[]>builder()
    .maximumSize(10_000)
    .build();

EmbeddingModel cached = new CachingEmbeddingModel(embeddingModel, cache);
----

The caching decorator intercepts `embed()` and `embedAll()` calls, serving cached results for previously seen text inputs and batching only the cache misses into a single delegate call.
